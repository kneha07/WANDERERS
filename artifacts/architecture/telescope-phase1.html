Candidates

1. The ladder as data: one survey stack drives opacity, cover and note

StrongSpec-backed: yes
Files
app/realsky.js 189-206 (scope, cover, deepFrame), 235-256 (note), 88 (drawEye fade); app/hips.js CONFIG.surveys; app/compass.js 257 and 362 (readers of cover()).
Problem
The Finder rung is spread over four places. scope() hard-codes the 3x to 6x ramp. deepFrame computes one opacity for one box. cover() knows only Deep or Finder. note() names surveyOf(R.survey).name and nothing else. Phase 2 adds Pan-STARRS (fade 60x to 100x, coverage Dec > -30). Phase 3 adds Hubble and Webb (above 300x, only inside a frame). With the current shape, each rung must edit all four places, and each place gets a new branch. That is low locality.
Change
Add the rung numbers to the survey entries that already exist in Hips.CONFIG.surveys: a fade range and a label. Replace scope() with one function in realsky.js that returns the visible stack for the current zoom and crosshair, for example [{ survey, opacity }], bottom first. deepFrame writes those opacities. cover() becomes the top opacity of the stack. note() names the topmost layer with opacity 1. Do not add a class or a registry. One array and one function are enough. The coverage test for phase 2 is one predicate on the entry (dec > -30).
Benefits
Leverage: phases 2 and 3 become "add one entry and one layer start", not four edits. Locality: the "note always names the survey on screen" rule holds by construction, because the note reads the same stack that sets the opacity. Tests: one table test (zoom and Dec in, stack out) replaces separate opacity and note checks for each rung.
Deletion test
Delete scope() today and its ramp reappears in three callers. The new stack function concentrates the ramp, the coverage and the label. It earns its keep.
Before
scope()      3..6 ramp
deepFrame    one opacity, one box
cover()      deep ? 1 : scope()
note()       surveyOf(R.survey).name
After
CONFIG.surveys.visible  { fade:[3,6], label }
CONFIG.surveys.ps1      { fade:[60,100], label, covers }
stack(zoom, centre) -> [{survey, opacity}]
deepFrame / cover / note read stack()

2. One survey loader with the timeout and backoff, used by every layer

StrongSpec-backed: yes
Files
app/realsky.js 126-171: DEEP, pickHost, startDeep, failDeep, setSurvey.
Problem
Two paths load a survey into Aladin. startDeep has the 20 s timeout, the start id that drops a late answer, and the 30 s backoff. setSurvey calls pickHost and setBaseImageLayer again, but has none of these. A hang there keeps the note on "Loading" with no limit. Phase 2 spec, section 3, says: "A startup failure in telescope mode must not retry every frame. Wait 30 s between attempts, and keep whatever rung below is working." That rule is for each layer. Today the backoff state (retryAt, failed, start) lives once, on DEEP.
Change
Move the guard into one function, for example loadSurvey(name): pickHost, the 20 s timer, the start id and the 30 s backoff, with the state kept per survey name. startDeep uses it for the base layer. setSurvey uses it and so gets the timeout for free. Phase 2 and phase 3 layers use it too. startDeep keeps only the Aladin start. This is mostly a move of existing lines, not new code.
Benefits
Locality: one place for "how a survey start fails". Leverage: three more layers with no new timer code. Tests: the two existing tests ("a failed start waits 30 s", "a start that hangs for 20 s") cover every layer through one interface.
Before
startDeep  pickHost + 20 s + id + 30 s
setSurvey  pickHost (no guard)
phase 2    ? copy again
After
loadSurvey(name)  pickHost + 20 s + id + 30 s
startDeep, setSurvey, Pan-STARRS,
Hubble, Webb  -> loadSurvey

3. One "phone steers the view" test instead of seven copies

Worth exploringSpec-backed: yes
Files
app/compass.js 214 (pose), 228 (track), 258 (updateHold), 305 (pointerdown), 318 (keydown); app/realsky.js 316 (drag solve), 328 (endDrag).
Problem
The expression S.sensors && !S.hold (or its inverse) is written seven times in two files. It means one thing: the phone's sensors steer the view. Phase 1 had to find and change each copy. A missed copy is a silent bug, for example a drag that moves the sight-check offsets while the view is held. Phases 2 and 3 do not change this rule, but they raise the zoom and add more users of the held view.
Change
Add one function in compass.js, for example const phoneSteers = () => S.sensors && !S.hold. Pass it to RealSky.init in the context object, as camOn is passed today. Replace the seven copies. No new state.
Benefits
Locality: the hold rule has one name and one place. Tests do not change, because they already drive hold through S.zoom and fed sensor poses.

4. Sidereal tracking through Sky.unobserve and Sky.observe

Worth exploringSpec-backed: no
Files
app/compass.js 222-233 (track, trackAt).
Problem
track() turns S.manual about the celestial pole with a hand-written Rodrigues rotation and its own sidereal rate. app/sky.js already converts between az/alt and the sky: Sky.unobserve and Sky.observe (used by syncDeep). So the same astronomy exists twice, and the copy in compass.js ignores refraction, which sky.js applies. Near the horizon at 300x (and at 800x in phase 2), that difference can move a target in the view.
Change
Keep the time step and the guards. Replace the rotation with one line: convert S.manual to the sky at the last time with Sky.unobserve, then back at the new time with Sky.observe. This deletes about six lines of vector math. Check first that the round trip has no drift at a fixed ?at= time; the existing tracking test covers that.
Benefits
Deletion and reuse. One module owns the sky geometry. The tracking test stays as it is.

5. Move the hold count out of note()

Worth exploringSpec-backed: partly
Files
app/realsky.js 234-247 (HOLDS, HELD in note); app/compass.js 256-271 (updateHold).
Problem
note() builds text, and also counts hold starts by watching S.hold change between frames. The count works only because note() runs every frame. The real event (hold starts) happens in updateHold, in another file. In phases 2 and 3 note() gains the rung label and the frame name, so its hidden state becomes harder to see.
Change
Count in updateHold where S.hold becomes true (for example S.holds++). note() reads S.holds. Delete HOLDS and HELD. Then note() is a pure text function of the state, and candidate 1 can feed it the stack.
Benefits
Locality: the event and its count are in one place. The test "the hold hint shows on the first hold" still passes through the note text.

6. Tests read the note and the opacity, not RealSky.DEEP

SpeculativeSpec-backed: yes
Files
test/realsky-telescope.test.js (13 reads of RS.DEEP or RS.R); app/realsky.js 514 (api exports R and DEEP).
Problem
The new tests are good: they run the real realsky.js with a fake page, a fake clock and a fake Aladin, and they mostly check what the user sees (note(), opacity(), cover()). But some asserts read DEEP.state, retryAt or failed. Candidates 1 and 2 change that state into one entry per survey. Those asserts would then break with no change in behaviour.
Change
When candidate 2 lands, change the internal asserts to the visible result (note text, box opacity, probe count in calls). Keep DEEP in the export only for selfTest and the browser check. Do not do this before candidate 2: today it costs work and gives nothing.
Benefits
"The interface is the test surface." Phase 2 tests can then be one more row in the same style.

Checked and kept

  • RealSky.cover() is a good seam. One number crosses from realsky.js to compass.js and drives the backdrop, the Eye stars and the hold rule. Keep it. Candidate 1 changes only how it is computed.
  • The pixel-based skip limits in syncDeep (180-186) hold at every zoom. They need no change for 800x.
  • cancelDrag() and cancelGesture() are small, but each has two callers with a real reason. They pass the deletion test.
  • No framework, no new file and no new dependency is suggested.

Top recommendation

Candidate 1: the ladder as data. Do candidate 2 first, as the first commit of the same change, because each layer in the stack needs the same guarded start.

Reasons:

  • It is the only candidate that makes phases 2 and 3 smaller. Each new rung becomes one survey entry plus one call to the shared loader.
  • It enforces the spec honesty rule by construction: the note names the layer that the opacity code shows.
  • It reuses Hips.CONFIG.surveys, which already holds the names and hosts that sw.js must agree on. Phase 2 must add Pan-STARRS there anyway for the tile roots.
  • It is about one function and two table fields. It deletes scope() and the special cases in cover() and note().

Do it at the start of phase 2, not as a separate refactor of phase 1. Phase 1 has one rung, so a stack of one is a hypothetical seam today. The second adapter (Pan-STARRS) makes it real.
